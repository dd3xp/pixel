### EXP-002 | 2026-08-16 | SD-πXL, 32色 DawnBringer32
- 目标: 蓝白色花瓣 → 16×16 像素画
- **prompt**: `a single flower petal, blue and white, simple, centered`（negative prompt 为空）
- 配置: 16×16, `assets/palettes/lospec/dawnbringer32.hex`, 10001步, guidance_scale=40.0, seed=0, teacher=SDXL, 初始化 palette-bilinear, init_distance=l1, lr=0.025
- 配置文件: `config/config_petal_db32.yaml`；日志: `logs/petal_db32_train.log`
- 输出: `workdir/config_petal_db32/2026-08-16-03-47-44-sdxl-im16x16-dawnbringer32/`（03-21-56 和 03-22-41 两个目录是夭折的启动残留）
- 中间结果: `png_logs/` 每 50 步存 `{step}_hard/soft.png`；checkpoint 每 5000 步
- 状态: GPU0 运行中（优化自 03:47 起；05:45 时已过 5000/10001 步 = 50%）
- **step 5000 中间观察**（样本已拉到本地 samples/）: 32色明显好于4色——已有浅蓝花体+蓝色花心+灰蓝背景的可读结构；但**花瓣轮廓未解析出来**，整体是菱形色块，2500→5000 变化很小（基本收敛）
- **关键发现（step 0→1000 退化序列，samples/db32_0/200/1000_hard.png）**: 初始化（palette-bilinear，即朴素缩小+量化）本来有白色高光和多档色阶；SDS 优化在 ~1000 步内把渐变/高光/光影全部磨平，塌缩成两档色的平色块。**单尺度 SDS 不只是保不住结构，而是主动破坏已有细节。** 机制: ① 16→1024 bilinear 放大+VAE 使像素级明暗对 SDS 梯度不可见/被当噪声惩罚 ② distorsion_prob=0.5 等增强使精细结构不稳定 ③ CFG=40 模式寻求 ④ fft 损失只锚低频。→ 论文 motivation 证据链：锚定机制是必需品，不是加分项
- 预期: 32色应足以表达花瓣曲线；CFG=40 偏高，可能过饱和（VSD/ISD 文献警示）
- ⚠️ **发现**: prompt 写的是 "a single flower **petal**"（单片花瓣），但 SDXL 选中的参考图 `select_sample.png` 是**一整朵花**（蓝心白瓣、蓝灰背景）——优化目标与字面意图不符，如确需"单片花瓣"需改 prompt 重跑
- 结果: **完成**（final 在 samples/exp002_final.png）。与 step 5000 几乎无差——**约 2500-5000 步即收敛，后半程步数浪费**。最终图：干净但平板，~4-5 色，无白色高光，无花瓣结构，蓝色方形花心

## P2 探索总结（2026-08-17 收摊，cron 已删）

**探索路径**: 006 锚定→007 t_max→008 强锚→009 source锚→010 主色池化→011/012/013 多图验证，共 8 个实验，全部 ~6 分钟量级。

**确认有效**:
1. 多尺度金字塔本身（EXP-004，P1 结论持续成立）
2. carry 锚定改善中间层质量（EXP-006 的 32×32 明显更饱满）——**当前最佳配置 = EXP-006**（头重脚轻步数 + 低层递增 carry 锚定 [0,0,10,30,100]）
3. 头重脚轻的步数分配（EXP-005 反面证实）
4. i2i 必须配对 prompt（EXP-011→012 修复对比），自动 caption 是必要组件

**确认无效/负结果**: t_max 压低（保碎不修复）、步数后移（侵蚀结构）、朴素主色池化（形状粘连）、锚定权重加强/换参考（16 级无感）

**核心科学发现（探索最大收获）**: 16×16 的瓶颈不是锚定/调度可解的——64×64 级在任何源图上都很好，说明压缩管线健康；崩坏发生在 64→16 的极限压缩段，且本质是**语义抽象问题而非信号处理问题**：复杂场景必须被"重新构图"（丢弃条纹背景、把花瓣合并成图标化形状——像素画家的做法），而现有机制（SDS+调色板+锚定）只会"压缩"不会"取舍"。次要发现：DB32 无亮黄导致花心失色——调色板覆盖度也是变量。

## P2b 尺度调度探索（2026-08-17 起，用户提出，cron 驱动）

**假设（用户）**: 信息损失与分辨率非线性——1024→64 丢得少、64→16 丢得多，故尺度采样应**前疏后密**，而非等比减半。
**调度函数**: s_i = T·(S/T)^((1-i/n)^p)，T=目标, S=起始, n=级数。p=1 即等比（现状基线）；p>1 尾部加密。p 为唯一超参。
**评判**: 16×16 花瓣结构完整性 + 忠实度，对比基线 EXP-006（等比+锚定, samples/exp006_final.png）与 EXP-004（等比无锚, samples/exp004_final.png）。

- **轮结论**: 简单图（flower1）质量已饱和，无法区分调度好坏；判决转移到复杂图
- [完] EXP-016 flower2 密尾 p≈2：比等比（012）略好——花心更凸显，但整体仍是噪声（samples/exp016_*.png）

**用户假设验证结果：成立且单调**——复杂图上 16×16 质量随尾部密度单调提升：等比(012) < p≈2(016) < p≈3(017)，且简单图上密尾无副作用（打平）。**推荐默认调度：p≈2~3 的密尾**（如 [128,64,48,32,24,16] 或更密九级版），flower1 上最佳单图结果 = EXP-014（密尾 p≈2 + carry 锚定）。

## P2c 背景释放函数探索（2026-08-17 起，用户提出，cron 驱动）

**假设（用户）**: 分辨率越低，背景的锚定权重应越低——让 SDS 的"磨平"副作用变成背景简化引擎，主体由 mask 保护。
**函数**: 背景锚定系数 β_i = ((s_i−T)/(S−T))^q（主体恒1），空间调制 w(x)=mask(x)+(1−mask(x))·β_i。q 控制释放速度。
**实现**: optimize.py 已支持 mask/bg_release_q/bg_weight_min；oracle 椭圆 mask（assets/masks/），自动分割（SAM/U2-Net）留作生产组件。
**评判**: flower2 16×16 上"背景是否变干净 + 主体是否更凸显"，基线 = EXP-017（同调度无 mask，samples/exp017_final.png）。

**队列与状态**:
- [完] EXP-018 q=1 / EXP-019 q=3：**均无效**——与 017 几乎一致，背景斑驳原封不动（samples/exp018/019_final.png）
- **诊断（重要）**: prompt 继承自 012，含 "on a blue and white striped background"——**最低层 SDS 还在捍卫条纹**。释放锚定只撤掉了"保忠实"的力，唯一能推平背景的力（SDS）被 prompt 指向了反方向。释放函数与 prompt 目标冲突 → 抽象机制需要 **prompt 层级调度**：高层忠实描述、低层抽象化描述
- [完] EXP-020 释放+prompt调度 / EXP-021 仅prompt调度：**突破——flower2 16×16 首次可读**（samples/exp020/021_final.png）：背景条纹被磨成均匀灰底，橙黄花心+花瓣团清晰成立，24×24 级雏菊完整背景平坦
- **归因**: 020≈021 → **prompt 调度是活性成分**，背景释放函数在此 case 增益≈0（锚定对象是 carry，上层被抽象 prompt 改变后 carry 自身已平，释放与否不再关键）。用户"低分辨率背景低忠实"的直觉由 prompt 调度在语义层实现
- [完] EXP-022 flower1 回归：**喜忧参半**——结构完好，但抽象 prompt 的 "blue flower" 注入源图没有的饱和青色（samples/exp022_final.png）。**简单图不需要抽象化，硬加会引入 prompt 驱动的颜色漂移**
- [完] EXP-023 seed=1 复验：与 021 高度一致（samples/exp023_final.png），**prompt 调度突破可复现**

## P2c 探索总结（2026-08-17 收摊，cron 已删）

**主结论**：
1. **prompt 层级调度是语义抽象的主力机制**：高层忠实 caption、低层抽象化 caption，flower2 16×16 从崩坏到可读图标（012→021），跨 seed 可复现。这实现了用户"低分辨率背景低忠实"的直觉，执行器是 SDS 的指令而非锚定权重
2. **背景释放函数 β_i=((s_i−T)/(S−T))^q 单独无效**（018/019），与 prompt 调度叠加增益≈0（020≈021）。保留为可选组件（遮挡/多主体场景可能有用），不进默认配方
3. **抽象化必须内容自适应**：EXP-022 证明简单图硬加抽象 prompt 会注入 prompt 驱动的颜色漂移。抽象 prompt 应从源图 caption 自动导出（保留源图颜色词），且只在背景繁忙时启用——与"自动 caption"组件天然是同一件事
